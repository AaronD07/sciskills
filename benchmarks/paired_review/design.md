# Does a scientific review skill repair the same draft?

A model produces a first submission from a real data packet. Two fresh sessions of the same model receive the same packet, files and prior work and review it. One receives ordinary review instructions. The other also receives a short workflow chosen from the requested artifact type before the first model call. The original draft supplies the no-review comparison. Each session can read and write files and execute Python through the same local tool.

Development uses 12 cases, three models and two attempts each. Holdout uses 24 new science tasks, eight per workflow, and eight financial investigations from different issuer filings. Each holdout task receives one draft per model and both reviews, including drafts that already pass. All sessions use the subscription clients with low effort. The protocol records the time cap, models, randomized schedule and content hashes. The graders, source repository, reference answers and hidden inputs are outside the participant workspace.

The primary outcome is the percentage-point difference in fully correct **science** submissions after skill review versus ordinary review, averaged over all task/model pairs. Equal budgets apply to both reviews. Report the 95% percentile interval from 10,000 paired bootstrap resamples of science source clusters, keeping all observations within each sampled source together. A gain of at least 10 points and a lower interval endpoint above zero meets the study criterion. The finance transfer set, per-skill and per-model breakdowns are secondary. Report repairs exclusive to each reviewer, regressions from correct drafts, review time, calls and failed sessions. Never stop or change tasks based on interim accuracy. An unresolved quota or infrastructure interruption is reported separately and a partial cohort cannot establish success.

The archive stores the public task materials, hidden references, submitted artifacts, Python call evidence, grades and schedule in separate locations. Fresh evaluations stage participant materials only. The same public cases should be used for replay and debugging after release. A new confirmation study needs fresh held-out material.

The holdout reviewers inherit the first model's final message as well as its saved workspace and Python code. A missing deliverable on a completed turn is a failed draft. A missing or interrupted client session is recorded separately. The primary success decision requires all science sessions to return successfully. If any are missing, also report the paired result for complete submissions alone. Each financial packet has its own issuer cluster, and each scientific dataset forms one source cluster across its three questions.

The reviewers see the source tables and necessary methods. Numerical and protocol tasks use structured outputs. Some include supporting records or a specified decision. No free-text judge evaluates scientific prose. Program tests check behavior at the requested entry point under multiple inputs. Development errors and their reproductions are in the [development notes](development.md).
