# LiveCodeBench programming tasks

These eight LeetCode problems come from the February–April 2025 contests in the sixth LiveCodeBench release. All carry the authors’ Hard label. The selection covers different algorithmic problems for which the inputs and outputs can be checked exactly with Python’s standard library. This is a targeted sample. The scores measure functional correctness under the local tool and time budgets. Marketplace software engineering and the wider LiveCodeBench leaderboard cover different workloads. The model receives the source question, including its public examples, plus the starter signature and local file contract. Each submitted function runs in a fresh macOS sandbox for every case. The scorer compares the exact JSON return value against every supplied public example and all 40 upstream private test entries for each problem. It uses 8 seconds of CPU time and 12 seconds of wall time per case. Capturing a digest of the returned value allows exact checks even when a correct result is a long string or a large list. The 320 private entries contain 274 distinct inputs absent from the corresponding public examples. The original tests stay in the host cache. These are published questions and tests, so exposure during model training is possible.

To populate the cache from the repository root, run `python3 -c 'from benchmarks.external_review.programming import cases; cases("dev")'`. The first load downloads the 134,303,240-byte shard into a temporary file and verifies its SHA-256. It caches only eight original records under `~/.cache/sciskills/livecodebench/`. Set `SCISKILLS_LCB_CACHE` to change the cache directory. Subsequent runs succeed offline. The manifest pins the source revision, shard and per-record hashes. The upstream dataset card identifies its license only as `cc`. This repository distributes the manifest and adapter. The source host supplies the problem text and test data.

The authors include self-repair as a distinct evaluation scenario. Google DeepMind reports LiveCodeBench for its Gemini 3.1 Flash-Lite model, and Qwen reports v6 results for its February–May 2025 window. Their evaluations differ in prompts, task mix and model settings from this experiment. For fixture validation we ran six independent Python solutions from the pinned WalkCCC collection, the Doocs trie solution for 3485, and an independent parity/product dynamic program using integer bitsets for 3509. Together they reproduced the 320 private test outputs. A sample-lookup implementation on 3509 passed all three public examples and failed all 40 private cases.
