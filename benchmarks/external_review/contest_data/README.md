# AtCoder contest stretch cohort

Seven AtCoder problems carry the Hard label in the published LiveCodeBench v6 code-generation release. They appeared in seven different contests. The AtCoder Problems model estimated their difficulties between 2,420 and 3,352 when we selected them. Those numbers are community estimates. Three problems form the development pool, with four different problems reserved for holdout. The cohort uses the standard v6 release. LiveCodeBench Pro is a separate benchmark. Participants see the original statement and examples plus a request to write a self-contained Python program. The host supplies one test's standard input to a fresh interpreter. The grader compares standard output with the original reference text, allowing a platform line-ending difference and one optional final newline. Each invocation uses the same macOS sandbox and 8-second CPU, 12-second elapsed and 2 MiB output/file limits as the LeetCode adapter. Models receive no test failures before review.

Every supplied public and private test is retained. There are 19 public examples and 280 designated private entries, with 275 distinct private inputs absent from the public examples after whitespace normalization. Seven independent Python reference programs passed all 299 checks. A lookup of the public examples passed all 19 public entries and four private entries that repeat public examples. The official lite release subsamples inputs and sometimes repeats a case. Full pass requires success on every entry. This evaluates correctness on the supplied inputs. For instance, the longest hidden Broken Wheel instance has 221 rim vertices, although the contest statement allows 1,000,000. These older public problems may have appeared in training. Scores reflect this specific subset and local environment.

Populate the cache from the repository root with `python3 -c 'from benchmarks.external_review.contest import cases; cases("dev")'`. The default cache is `~/.cache/sciskills/livecodebench/<revision>/`. Set `SCISKILLS_LCB_CACHE` to use another directory. The first fetch validates the 134,303,240-byte source shard. Subsequent runs verify the SHA-256 of each selected record and can run offline. The upstream dataset card labels the license `cc`. The repository distributes task IDs, hashes and the adapter. The source host supplies the original problem text and judge data.
