# DABstep payments transfer tasks

These questions come from the ten labeled developer items released by Adyen and Hugging Face. Seven carry the authors' hard label. The calibration set contains IDs 1273, 1464 and 1871. They ask for an average fee, rule eligibility given two attributes, and the impact of changing a fee. IDs 1273 and 1871 appeared in the earlier project pilot. Item 1305 repeats the average-fee template and is excluded. [Pinned release and public labels](https://huggingface.co/datasets/adyen/DABstep/blob/77af25c3b87de35f6db336e429aae013d67c96a0/data/tasks/dev.jsonl)

The two holdout items, 1681 and 1753, ask which rules apply to one merchant during a day and a month respectively. They share one template, one merchant and the underlying transactions. Count them as two related examples of a single transfer family. The labels were public before this experiment. The authors' hidden test results provide historical context only. Their best baseline, o4-mini, solved 14.55% of the hard test split in the 2025 paper. [DABstep paper, Table 1](https://arxiv.org/html/2506.23719v1)

We checked the fraud-rate definition against both holdout labels using every row for the merchant in its calendar month. The manual defines fraud as fraudulent volume divided by total volume and specifies euros for monthly volume. The two definitions below produce identical fee-ID sets in both cases. The January rates fall in different fee bands, but those bands make no difference for the 37 transactions on January 10. A correct final set alone cannot establish that an agent computed the rate correctly. [Manual, sections 5 and 7](https://huggingface.co/datasets/adyen/DABstep/blob/77af25c3b87de35f6db336e429aae013d67c96a0/data/context/manual.md)

Eligibility does depend on which transactions and time window the analysis uses. Dropping refused transactions removes IDs 709 and 741 on January 10 and leaves March intact. Using January 10 alone for the monthly aggregates substitutes 895 for 454. Taking monthly euro totals separately for each card scheme makes the same substitution on January 10. In March, scheme-level totals drop 454 and add 154, 319, 470 and 895. The published labels agree with using all transactions and merchant-wide calendar-month totals. These sensitivity checks do not change the frozen grader.

Item 2697 was excluded during reference validation before agent evaluation. All 94 January fraud transactions use ACI G. Applying every eligible fee rule to each transaction gives €61.05 for G and €77.68 for the lowest-cost alternative, E, an increase of €16.63. The release labels the choice E and the cost €13.57. The documented calculation reproduced the choice, but the reference cost remains unresolved. We retained the upstream label in the unmodified cache and omitted the item from both splits.

Running `python3 benchmarks/external_review/payments.py` downloads and checks the original seven context files, labels and license. It caches them under `~/.cache/sciskills/DABstep/<revision>`; set `SCISKILLS_DABSTEP_CACHE` to change the cache root. Each task receives the original question and guidelines, a one-sentence JSON output instruction, and all seven context files (138,236 payment rows). The label file and manifest stay outside the task workspace. Evaluator-side gold values come directly from the pinned release. The local comparison uses unordered fee IDs and absolute numerical tolerances of €0.0000005 for the six-decimal average and €0.0000000001 for the counterfactual to allow different orders of floating-point summation. The official leaderboard uses its own grader.
