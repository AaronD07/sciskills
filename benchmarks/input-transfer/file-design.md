# File-edit replication

This is a follow-up on the same two public problems after observing that eight of the ten failed insertions in the response-only trial contained invalid Python. The cases are reused. The question is whether skill-assisted agents do better when the measured deliverable is the file they write. We will run 24 fresh sessions using the frozen fresh-input skill, the same models and original task wording, original graders, and three randomized baseline/skill pairs per agent and problem. Each attempt receives a new workspace containing TASK.md, an empty solution.py, and the skill file in treatment. Status messages are free-form. The actual solution file is graded without extraction or whitespace normalization. We keep every run with its original assignment and apply the original descriptive decision criterion. This is not an independent holdout.

The common instruction allows reading and editing only within the workspace and directs the agents to leave execution to the independent grader. Claude Code uses restricted mode with Read, Edit and Write confined to the workspace. Codex uses workspace-write with its native patch and shell tools. Tool implementation differs, so record tool counts and Codex shell commands. Review the resulting traces for out-of-scope actions before interpreting the results. Use independent signed-in client preflights and the same subscription checks as the response study.
