# Prospective input-transfer protocol

The earlier DS-1000 pilot suggested two distinct explanations for apparent failures: agents sometimes rebound example inputs, and the request for a complete file may itself have encouraged rebinding. This follow-up supplies an unambiguous insertion contract to both conditions and asks if the fresh-input workflow improves correctness beyond that prompt.

We selected two public DS-1000 problems before collecting responses. In 108, the agent joins two event tables using timestamps. The two official tests change the entries to be joined. In 411, the agent extracts an image window with zero padding. Its three tests vary the array, window bounds and side requiring padding. Neither problem belongs to the earlier pilot. Both have distinct supplied-input cases, an executable reference and a deterministic grader in the pinned environment. Selection was based on those criteria and relevance. It does not yield a representative sample of DS-1000.

The primary outcome is a pass on the full, unchanged upstream grader. Compare three paired repetitions of baseline and skill per problem and per model, 24 sessions total. A meaningful pilot result would be at least two additional full passes in the skill condition across the 12 held-out pairs, with more gains than regressions and some evidence of a gain on both problems. Report per-problem and per-model outcomes regardless. This threshold is descriptive; two tasks cannot establish broad effectiveness.

Each session gets only the common insertion instructions and original problem prompt. Treatment appends the complete skill. Graders, answers and other sessions stay outside the prompt. Clients return source without tools under a common 180-second limit and low reasoning effort. Run order is seeded; at most four sessions are active at once. Record timeouts and other client failures distinctly. Compare baseline and treatment within each agent, problem and repetition. The runner requires ChatGPT login for Codex and first-party Claude subscription login with extra usage disabled for Claude Code. Both subprocesses receive an allowlisted environment.
