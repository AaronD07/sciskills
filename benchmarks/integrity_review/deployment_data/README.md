## What the evaluator measures

For a new-unit task, whole research units are selected in stable hash order for independent reserve, public validation, or fitting. For a future-visit task, each public assessment observation comes after the lock and every reserve observation comes strictly later than that unit's entire public history. In both modes the independent reserve stays outside the workspace. A source label and a target population apply to both twins. The compromised twin has erroneous archived split assignments. Its reported scores are the actual scores for that filed split. An intact handoff uses every designated observation in its intended role.

The regression reference uses pooled least squares. The candidate adds a within-unit residual calibration, falling back on the equally weighted mean of observed unit offsets for a new unit. With a balanced fitting cohort this fallback can match the reference exactly; the specified tie rule preserves the reference. The HAR reference uses nearest centroids. Its candidate uses a three-neighbor vote, preferring calibration windows from the same wearer when available. These deliberately small pipelines keep the experimental comparison identical across clients.

Participants submit an executable *declarative* recipe and row membership in release.json. The evaluator executes the frozen recipe on the named fitting rows, predicts reserved outcomes, and checks predictions and realized loss against the independently required release. The reported choice is determined by public admissible validation. Private performance need not favor the same model on a finite reserve. The archive records both recipes' private losses to make this distinction inspectable. The benchmark evaluates a participant's selection and validation of supplied models. It does not claim the participant trained an original estimator.

Run `python3 benchmarks/integrity_review/deployment_data/verify.py` with NumPy for an independent check. It rebuilds each public evaluation from the participant's original CSVs, compares a separate matrix-based fit and nearest-neighbor implementation on both public and private data, verifies disjointness or strict time order, and exercises acceptance and rejection of concrete release artifacts. The measured clients only need Python's standard library.
